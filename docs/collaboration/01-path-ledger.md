# 道路 / 方法台账规范

## 目的

让任何人打开题目目录就能回答：

- 已经试过哪些方法？  
- 各自假设与结果？  
- 为什么废弃或采纳？  
- 还剩哪些候选路？

避免「换人从头找路」和「同思路撞车」。

## 公开仓硬规则（防后人重复造轮子）

本仓为 **公开仓库**。算子开发中的**每一次探索**（含失败、半途而废、AI 试错、性能死胡同）都必须落盘，不得只留在聊天或本地脑子里。

| 必须记 | 可以不单独开篇 |
|--------|----------------|
| 新假设 / 新切分 / 新指令序列 / 新依赖版本 | 纯错别字、格式化 |
| 编译/精度/性能一次完整尝试的结论 | 未开始就放弃且无任何改动 |
| 废弃原因（尤其「为什么别再试」） | — |
| 云上实测数字与日志相对路径 | — |

**未写入本仓文档的探索 = 对公开协作者不存在**；后人有权按台账重复未记载方向，造成的浪费由未记账方负责。

探索落盘最低组合：

1. `path-ledger.md` 一行（必有）  
2. 较复杂时加 `explorations/EXPxxx.md`（过程、命令、现象、结论）  
3. 换路/止损加 `decisions/DECxxx.md`  
4. 当日流水进 `dev-log.md`

## 文件位置

```text
tasks/<active|archive>/<题名>/
  path-ledger.md              # 总表（必维护）
  explorations/               # 单次探索长文（推荐）
    EXPxxx-短标题.md
  decisions/DECxxx.md
  dev-log.md
```

模板：`docs/templates/exploration.md`

## 每一行最少字段

| 字段 | 说明 |
|------|------|
| ID | `P001` 递增 |
| 日期 | YYYY-MM-DD |
| 作者 | 账号/花名 |
| 阶段 | 设计 / 功能 / 精度 / 性能 / 交付 |
| 假设 | 一句话：为什么觉得这条路有效 |
| 方法 | 具体改动点（模块/策略），勿写空话 |
| 时限 | 例如 4h / 1 天；到期必须结案 |
| 证据 | 日志路径、profile、对比表链接 |
| 结果 | 量化：精度是否过、耗时 vs TBE、编译是否过 |
| 结论 | `采纳` / `废弃` / `挂起(原因)` / `需决策` |
| 耗时 | 实际投入 |

## 状态机

```text
规划中 → 进行中 → 结案(采纳|废弃|挂起)
                    ↘ 需决策 →（会后）结案
```

「挂起」必须写恢复条件；超过 7 天无恢复条件 → Reviewer 可改为废弃。

## 开新路前检查

1. 搜本仓：`path-ledger` 关键词（例如 double buffer、atomic、单核、仿真）  
2. 搜同类归档题：`tasks/archive/**/path-ledger.md`  
3. 若高度相似且已废弃：除非有**新证据**，否则不得重开

## 好例子 / 坏例子

**好**：`P012 | 性能 | 假设全核 + UB 双缓冲可消等待 | 改 Kernel pipeline；对比 case P-allcore | 时限 4h | 结果 大 shape 1.02×TBE，小 shape 仍差 2us | 采纳大 shape；小 shape 走仿真豁免`

**坏**：`试了下优化，好像快一点`（无假设、无时限、无数据、无结论）

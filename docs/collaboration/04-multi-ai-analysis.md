# 开题前：多路 AI 优化分析（≥3）再汇总

## 目的

每道题在写设计/动代码之前，先做**相互独立**的优化与实现路径分析，降低「第一条路走错 → 反复换路」的成本。

## 硬规则

1. **每题至少 3 份**独立分析（不同模型 / 不同人 / 不同视角均可），再出 **1 份汇总**。  
2. 分析与实现**分阶段**：汇总未完成前，禁止进入深度编码与性能专题。  
3. **题目隔离**：分析、台账、材料、决策只写在该题目录下，禁止串题、禁止把 A 题结论直接粘到 B 题当事实。  
4. 你是其中一路即可；其余路由其他 AI 或同事完成，**不得由同一路代写三份凑数**。

## 目录约定（每题）

```text
tasks/<active|archive>/<题名>/
  analysis/
    README.md           # 本题分析进度与隔离声明
    AI-1_<来源>.md      # 分析 1
    AI-2_<来源>.md      # 分析 2
    AI-3_<来源>.md      # 分析 3
    SUMMARY.md          # 汇总：采纳路径 / 废弃路径 / 争议点 / 有界优化顺序
  materials/            # 仅本题模板与只读材料
  path-ledger.md
  ...
```

禁止把分析写进其他题目目录或仓库根「大杂烩」文档。

## 单份分析最少包含

- 语义与验收门禁理解（含小 shape 豁免是否适用）  
- 最简正确实现路径  
- 性能候选路径（有序、有止损）  
- 明确「不要先做」的反模式  
- 对本题特有风险（广播、dtype、比较方式等）

## 汇总规则

`SUMMARY.md` 必须：

| 项 | 要求 |
|----|------|
| 共识 | 三路共同认可的基线路径 |
| 分歧 | 列出并裁决（Owner 拍板） |
| 执行顺序 | P0 正确性 → P1 全核标准优化 → P2 仅门禁未达标再专项 |
| 废弃清单 | 三路已否定且无新证据不得重开的方向 |
| 回写 | 把采纳项写入本题 `path-ledger.md` |

## 与阶段的关系

```text
认领 →【≥3 AI 分析 → SUMMARY】→ 设计 → 最简实现 → …
```

该步骤插在「抄齐任务书」之后、「设计 PR」之前。

# J045：固定 tile/核数的连续 flat 通道块对照

结论：不升级基线，保留 J035。J045 精度通过，但多个适用大通道输入四轮稳定变慢；目标 `[127,8192,1]` 的低精度 profiler 小幅均值收益随顺序翻转，无 profiler 对照也没有支持提速。不能据此推导官方五点性能。

## 改动及历史核查

J035 的 `op_kernel/p_relu_grad_update_splitc.h` 是唯一修改文件。Host 路由、tileLen、blockDim、UB 分配顺序/大小、数学计算和同步保持原实现；把“每核固定 C 块跨 N 遍历并常驻权重”改成“每核连续 flat 通道 tile 区间，逐 tile 用向量 DataCopy 读取权重”。没有逐元素标量展开。

这是一项任务组织策略对照，包含遍历顺序和权重驻留策略两个相互关联的变化；不能把结果单独归因于重读权重。C 尾块时每核 tile 数直方图不变，但每核字节负载分布可能改变。后续若只验证权重常驻价值，应保留 J035 原 batch/C 遍历，仅改变权重生命周期；本轮没有冒充完成该纯对照。

历史 J023 已是连续 DataCopy 权重的向量路径，不是 P105 逐元素路径。J024 引入 split-C 后，旧同轮 `[127,8192,1]` Task：FP32 14.180→11.895、FP16 17.700→12.940、BF16 17.785→13.072 μs。但旧实验同时改变 tile/任务分布，不能代替当前 J035 固定布局对照。J014/J015 的重复权重搬运/UB 展开用于另一条合并路径，亦不是本次 split-C 严格权重生命周期对照。

## `[127,8192,1]` 的实际切分

三 dtype 均为 tileLen=4096，C 分成 `[0,4096)` 与 `[4096,8192)`，无通道尾块。Host maxTile：FP32 5184，FP16/BF16 4288；`cTiles=ceil(8192/maxTile)=2`，对齐后 Ctile=4096，batchGroups=40/2=20，blockDim=40。

J035 core=k：C 块编号 `k/20`，batch 组 g=`k%20`；N 区间 `[floor(127*g/20), floor(127*(g+1)/20))`。每个 C 块有 13 组处理 6 个 batch、7 组处理 7 个；全芯片 26 核×6 tile、14 核×7 tile，总计 254 tile。每核处理 24,576 或 28,672 元素。每 tile 输入/输出连续 4096 元素，下一 batch 起点跨 8192 元素。

每核权重首次读取 4096 元素，FP32 为 16 KiB，FP16/BF16 为 8 KiB；后续 5/6 tile 复用。已核原 Compute：低精度每个 tile 仍 Cast 权重到 negLocal 再 Mul，没有缓存 FP32 转换结果；J045 保持这个行为。J045 改为连续 flat tile，每 tile 重读对应 C 块权重；权重逻辑读取从 20*C 增至 127*C，全部逻辑 GM 读写由 `(4*127+20)*C` 增至 `5*127*C`，约 +20.27%。这不是实测 HBM 流量，不预设 L2 容量、延迟或命中。

依据：J035 `op_host/p_relu_grad_update_tiling.cpp:237`、split-C Init/Process；J043-mapping-audit.json 的实际 Block Num 40 记录，以及 J045-mapping-audit.json。

## 真实设备验证

- Ascend910_9362 / ascend910_93 / CANN 9.0.0。FP32、FP16、BF16 原生构建成功。
- 111 个适用历史输入索引覆盖检查通过；真实设备 780/780 精度案例通过；57 个边界/模式输入共 5,184 次调用、10,368 个输出检查通过。有限数值集，未宣称覆盖所有 IEEE 特殊值。
- 普通 profiler：30 输入（12 小、18 大）、四轮 ABBA/BAAB/ABBA/BAAB，后两轮反转输入顺序；每组 250 次，统计 101–250 次的 Task Duration 中位数，再平均同轮两个位置，最后平均四轮。480 组、120,000 条 kernel 记录，输出检查通过。
- 无 profiler：12 输入，四轮同样交替；每窗口 4×128 预热，12×128 连续 enqueue，统计后 10 个 event 批间隔/128 的中位数。192 窗口、2,304 个 event 样本。该值是连续提交吞吐间隔，含主机送入等因素，不能直接当隔离 kernel 时间。
- 编译 ELF：每 dtype 的 15 个入口中仅对应 split-C 的 1 个函数字节改变，其他 14 个相同（FP32 后缀12、FP16后缀13、BF16后缀14变化）。未改路径仍有计时偏移，是漂移控制，不是算法收益。

无 profiler 首次启动因本地生成 shell 的 CRLF 失败，未构建/未执行测试；确认原进程退出、测试目录不存在后，保留失败日志并用 LF 脚本恢复。恢复作业及其他设备作业全部退出 0。没有重复启动结果未知的设备任务。

## 如何解读结果

多个大输入明显回退，不支持用 J045 替换 J035。低精度目标在 profiler 前两轮变慢、后两轮变快；不能采用小幅四轮平均收益。无 profiler 下 `[91,10368,1]` 三 dtype 每轮都慢，支持回退不只是 profiler 造成；但未改 C=32 路径也出现约 0.5 μs 均值偏移，因此不把所有差额都归因于算法。

普通 profiler 的 MTE2、Vector 活跃时间可以分别报告，但会重叠，不能相加形成独占耗时，更不能把比值称作耗时分摊。graph PMU 有 J044 已证实的归一化异常，本轮没有用它。

用户随后确认官方 1148578 源码与 J035 完全一致，本文接受此确认作为平台基线映射；本轮工具未下载提交快照做逐字核对。官方 Pass 的五点为 7.15/7.29/7.11/5.88/6.06 μs，shape/硬件/采样口径仍未知。J045 从未提交。

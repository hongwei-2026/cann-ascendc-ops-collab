# J040：公开 repeat Select 接口实验

本轮以 J038 为直接基线，保留 J035/J038/J039 原版。只将 split-C 中两次 count Select 改为公开 repeat 重载，保留两次调用后的显式 PIPE_V。没有修改 Compare、Cast、算术、UB布局、队列、tiling、分核或主机路径；没有提交比赛或推送。

## 依据和适用条件

实机为 Ascend910C / ascend910_93 / dav-c220-vec，CANN9.0.0，driver25.5.5，40 Vector核。启动前 NPU 无运行进程，J039 两个设备任务退出0。

采用本机官方安装头文件作为当前版本的直接依据，快照及 SHA 在 `J040-api-evidence/manifest.json`：

- `kernel_operator_vec_cmpsel_intf.h:182–185` 声明公开连续 mask/repeatTime/BinaryRepeatParams 重载。
- `kernel_operator_vec_cmpsel_intf_impl.h:504–521` 将其转到架构实现。
- `dav_c220/kernel_operator_vec_cmpsel_impl.h:252–264` 先准备模式2选择掩码，再设置 float 向量 mask，最后发出 repeat vsel。相比159–198的 count 路径，没有 SetMaskCount/ResetMask/SetMaskNorm 切换及末尾 PIPE_V。
- 该头文件 SHA256：`9a0e66e77d4e6dac930b0a9913ba560695d8d29b9d08fdeaad41a4ca0a323705`。它的34–64行依然通过临时UB地址、Duplicate和屏障准备CMPMASK，因此本实验没有消除全部掩码设置成本。
- `kernel_struct_binary.h:40–60` 确认构造参数顺序为 dst/src0/src1 的 block stride，再是三者的 repeat stride；SHA256 `fb4e8aad1930d8b502010b23d15c20b7739b9aeca5f9113778b1b52a2f05eed8`。
- `dav_c220/kernel_operator_vec_cmp_impl.h:138–161` 的 CompareCompute 按256字节块生成连续比较位，不切换 count mask 模式；SHA256 `a1c76ba24eac17c74a2e9da0e96bd10edf7264bf16ad6e36d39a24d8c9578f3b`。本轮保持原 Compare(+zero)，没有复用历史失败的 CompareScalar。

原代码的 `cmpCount=AlignUp(currentNum,64)` 与 UB 分配范围已经保证整64个float。新参数为 mask64、repeatTime=cmpCount/64，stride `{1,1,1,8,8,8}`；一个32字节block、8个block组成256字节连续repeat。FP32路径最大5184元素，即81次；低精度存储路径计算仍为float，最大4288元素，即67次。无需拆分或新加形状分支。

模式2每次Select重新传入同一个mask基地址，选择位随repeat数据推进；模式0复用CMPMASK的语义不适用于这里。两次Select的输出分别是updateFloat/dxFloat，输入为mask、zero/fg及grads/neg。保留第一次调用后的PIPE_V，避免下一次掩码重置/临时UB复用与前一次vsel交叠；保留第二次之后的PIPE_V，保护后续Cast/输出依赖。原来的尾部填充与CopyOut(currentNum)保持不变。没有调用私有intrinsics或使用isSetMask=false。

## 正确性和压力

复用 J039 的780个精确输入和golden，其中24个专门模式覆盖 `[81,8256,1]`、`[97,10336,1]` × 三dtype × 逐元素交替、每64元素交替、batch符号翻转、通道维末129位置为负，并插入零值。这验证了跨repeat掩码推进、每次调用掩码重置和尾段行为。其余756例覆盖既有分支、边界和留出形状。**780/780通过**。

57组压力输入：原33组各64次、24个掩码模式各128次，共 **5184次调用**。每次先污染两个输出缓冲，再取回dx/update与golden逐元素比对，合计10368项输出检查全部通过；有符号零按数值零等价。均为有限数测试，不声称覆盖全部IEEE特殊值。

## 决定与限制

**决定：语义和已测正确性成立，性能证据有混杂，J040 暂不替换 J038；保留为实验版。J035/J038/J039 原版全部保留。**

完整计时中，33个组合均值均下降0.0802–0.3611 μs，21个四轮均快。排除5个未修改控制组合后，28个实际修改路径中19个四轮均快、0个四轮均慢。这是观察到的正向结果，不能省略。

但5个控制组合也全部均值下降0.1137–0.2773 μs，其中C=1的FP32和BF16同样四轮全胜。它们不走本轮修改的split-C路径，不能用repeat Select解释下降。因此，即使四轮全胜，也不足以单凭这些数据证明因果收益。J038 A/A的同轮有符号差为−1.520…+1.820 μs，J040 B/B为−2.059…+1.460 μs；不是置信区间。

现有工具能确认公开repeat重载的实际实现、编译产物、正确性以及上述计时，尚不能分离全部共同偏移的来源。本机llvm-objdump此前已确认无法解码这些设备指令；本轮不重试安装或更改工具链。没有证据把偏移具体归咎于频率、缓存或某一流水。

本轮固定候选到此结束，不按平均差继续扫参数。若后续要决定采用，最小补充证据是针对一个修改路径和一个同dtype未修改路径，做独立单shape进程的交错A/A与A/B并交换版本标签顺序，检验共同偏移是否仍存在。此补充实验本轮未运行，不能把当前差值减去控制差值就当成已证实收益。

用户追加的小通道查询已单独保存到 `SMALL_CHANNEL_HISTORY.md`：J035/J038/J039的近期性能集中只有 `[600000,1,1]` 是小通道，仍有60万元素；没有小N、小C、低总元素量的近期性能样本。跨实验数值不拼成单次对照。

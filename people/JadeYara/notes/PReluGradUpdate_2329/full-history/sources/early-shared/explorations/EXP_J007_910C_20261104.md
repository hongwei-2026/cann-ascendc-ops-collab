# J007 — J003多tile输入预取实验

基于已测J003，仅把grads/features输入队列改为双缓冲，初次预载当前tile，之后在Compute当前tile前发起下一tile的CopyIn；dx/update输出仍单缓冲。原Compute公式、Compare/Select、转换和同步保留。推进使用实际currentNum，预取也在通道边界截断。

Host UB系数FP32 25→33，FP16/BF16 33→37，对应多一份grads/features缓冲。额外UB占用可能缩小tile，因此收益必须与增加tile次数的成本一起测量。没有把本实验叠加到J004的S=1权重向量路线。

三dtype原生构建成功；96/96实机精度通过，包括18组UB/通道专项、24组扩展、30组分支/大输入、24组随机边界。FP32/FP16/BF16各32组。96组使用独立广播golden，有限输入精确逐元素比较。本地执行器曾在72组完成后断开；核实其余24组未运行且无活动进程后，仅续跑剩余部分，改用独立日志作业以免再次受控制会话中断影响。

## 同机两轮性能

J003→J007 / J007→J003交换顺序，每组25调用、丢弃前5次预热，保留20样本。下表为两轮msprof Task Duration中位数，单位μs。16次性能采样最终输出全部正确。

| 输入 | J003 μs | J007 μs |
|---|---:|---:|
| [17,3,1025] FP16，w=3 | 6.700 / 8.200 | 7.160 / 7.460 |
| [600000,1,1] FP32，w=1 | 9.180 / 9.160 | 9.480 / 9.889 |
| [600000,1,1] BF16，w=1 | 9.180 / 9.369 | 8.840 / 10.040 |
| [2,3,65] BF16，w=3，小输入对照 | 4.900 / 5.040 | 5.020 / 5.080 |

结论：当前J007输入预取/双缓冲方案不采用，J003通用候选与J004 S=1专项候选保持不变。

大FP32 [600000,1,1] 两轮分别慢0.300/0.730μs；普通FP16 [17,3,1025] 第一轮慢0.460μs、第二轮快0.741μs；大BF16第一轮快0.340μs、第二轮慢0.670μs，收益方向不稳定。小BF16对照两轮慢约0.120/0.041μs。没有把某轮最低值当作已实现加速。

profiling也未给出一致改善：大BF16第一轮MTE2 ratio由0.3925降至0.3485、耗时小幅下降；第二轮J007为0.4245、J003为0.406，耗时反而增加。流水线ratio可重叠，不能简单相加；这些数据只支持当前方案没有稳定总耗时收益，不足以单独确定某条指令的因果成本。

该实验同时增加输入缓冲和提前搬运，并按实际新增缓冲提高UB系数；更小的maxTile及队列调度成本可能抵消重叠收益，这是待进一步隔离的解释。后续更有价值的候选是先复用中间缓冲、降低UB占用，再重新评估tile/预取配置；本轮未实施该候选，也未承诺4–5μs。

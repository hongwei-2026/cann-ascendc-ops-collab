# J038：split-C 零向量跨 batch 复用

本轮基于冻结的 J035，只验证一个新假设：将每个 batch 重复填充的零向量变为每核初始化一次。未修改 tile、分核、路由、输入搬运、算术或原有同步；没有提交比赛或 push。J035 和全部历史候选均保留。

## 依据与实现

J035 在 [127,8192,1] 上每核执行 6–7 个 batch，同一个零向量被 Duplicate 6–7 次。已有硬件分段显示 FP32 第二个 Compute 约 924 周期；完整 Scalar/Vector/MTE2 活动彼此重叠，不能仅根据占比判定独占关键路径。本轮用可明确删去的重复向量操作检验仍有多少有效收益，不重复无收益的预取、队列合并或提前释放。

J038 在 Init 新增常驻零 TBuf 并填充一次，Compute 只读取它。保留 Compare(+0)、count Select 和所有已有 PipeBarrier，未使用曾失败的 CompareScalar 或掩码乘法。新增缓冲位于原有分配之后，前置 256 字节，使零数据保持原 dx 别名的 modulo512 地址相位，避免破坏 J034/J035 已验证的源操作数布局。原缓冲地址不变。最大实际 UB：FP32 174592 字节，FP16/BF16 170560 字节，均低于本机扣除预留后的 188416 字节。逐个可达 64 对齐 tile 的容量/相位核算在 J038-allocation.json。

这沿用已参考的 upstream split-C 跨 batch 复用不变量的思路；权重复用已在 J024/J026 实现，本轮新增的是常量零，不直接移植 arch35 实现。[官方 API 列表](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0003.html)及 [Compare 对齐要求](https://www.hiascend.com/en-sg/document/detail/en/canncommercial/850/API/ascendcopapi/atlasascendc_api_07_0066.html)作为接口依据，本机 CANN9 编译和实板测试作为最终证据。

源码只改 op_kernel/p_relu_grad_update_splitc.h。编译后每 dtype 仅对应 split-C 函数变化，其他 14 个函数字节相同；FP32 6608→6748 字节，BF16 7036→7140，FP16 7312→7288。常量生命周期和地址均改变，不能把全部周期差简单归因于一条 Duplicate。

## 判定与限制

本轮保留 J038 为有依据的增量候选，不替换冻结的 J035。28 个实际 split-C 改动组合的平均延迟都下降，17 个四轮全胜、0 个四轮全败，另外11个至少有一次反向或持平。未改动路径有5个组合：FP16/BF16 [107,15424,1] 超过低精度三块路由范围，以及三 dtype [600000,1,1]；其平均差 +0.036～+0.120 μs，说明本轮运行状态偏移依然存在。不能把所有版本差都当源码收益。

新增留出 [113,12864,1] 三 dtype 全部四轮更快：FP32 12.532→12.225 μs，FP16 13.885→13.481 μs，BF16 14.130→13.781 μs。另一个新输入 [83,10336,1] 的 BF16 四轮均胜，FP16/FP32 有反向轮次。没有按这些单点增加任何选择规则。

原目标 [127,8192,1] 的 J035→J038 平均值为 FP32 10.912375→10.838625 μs、FP16 11.9283125→11.639750 μs、BF16 12.0460625→11.839625 μs。四轮差值分别为 FP32 −0.12450/−0.12000/+0.15000/−0.20050，FP16 −0.33000/−0.79950/+0.01050/−0.03525，BF16 −0.34475/−0.1905/+0.0090/−0.2995 μs（精确值以 JSON 为准）。目标点不是四轮稳定获益；同版本 A/A 中位数差总体范围 −1.080～+1.600 μs，不能用总体均值覆盖该限制。

硬件分段提供了独立的局部机制证据：FP32 第二个 Compute 924→857/858 周期，FP16 1264→1163，BF16 1340→1227；两轮反向顺序一致。零向量跨 batch 复用减少了可观测 Compute 成本，但 bank 冲突比例上升，普通 profiling 的 MTE2 活动时间也略升。各流水重叠，不能把这些数字相加推算整算子收益，也不能由此宣称 HBM 带宽饱和或确定唯一剩余瓶颈。

尚未达到大输入4–5 μs。下一项最有依据的独立候选是：本轮常驻零消除了 `zeroLocal=dxFloat` 别名，原先两次 Select 间因“先读 dx 作为零、后写 dx”而需要的依赖现在已改变；可在核对 API 隐含依赖后，单独检验该处 PIPE_V 是否仍需要。仅这是后续假设，本轮没有删除这处或任何原有同步，不能提前宣称效果。无需重复已经排除的预取、队列合并或输入提前释放扫描。

# J018：整核权重驻留的相位修复与实机验证

J018 修复了 J016 的通道相位错误，462 个独立精度输入全部通过；四版本交替测试 1072 组的最终输出全部通过。整核驻留路径有可重复收益，但未触发驻留的 S=1 路径有回退，因此保留为专项候选，不全量替换 J013/J015。

## 实现与失败原因

J016 基于 J015：对齐 S=1、多 tile，tileLen 向下对齐通道数 C 后不增加每核循环数时，令 tileLen 为 C 的整数倍；首次装载并展开权重，保持权重队列张量至本核结束，后续 tile 复用。

旧 mergeWeights 条件只有 tileLen>C。低精度 C=4096 时，Host 可能把 tileLen 从 4288 下调为 4096；驻留已启用，但 mergeWeights 为 false，Process 又在通道边界截断 currentNum，第二次迭代的权重相位随之改变。J018 只把条件改成 `(tileLen_ > channelNum_ || residentWeights_)`，避免驻留模式重新截断通道。没有新增 buffer 或更改算术、归约语义。该算子输出逐元素 update，此实现不含跨元素归约。

source ZIP SHA-256：`b32e33df1cb55e09bf3fc0a0be6d44c03d075282c9ce102e306d238d72180932`。完整最小修改见 J018.diff；Host 与 J016 相同。

## 适用路径与回退

按本机参数及实际 Host 代码计算，69 输入中 28 个触发驻留；其四轮平均全部快于 J015，改善 0.488–7.042 μs，27 个每轮均至少快 0.15 μs。这里是 Host 规则计算，不是额外插桩读取 tiling；计算值保存在 analysis-with-host-rule.json。余下 41 个对照没有驻留收益，7 个每轮至少退化 0.15 μs。

触发规则依赖容量和循环数，不是 shape 白名单。例如 BF16 [1201,512,1] 的 blockFactor=15376，原 tile=4288，向下对齐为 4096，都是 4 次循环，允许驻留；[2001,512,1] 的 blockFactor=25616，4288 为 6 次、4096 为 7 次，不允许驻留；[1001,512,1] 同理从 3 次变 4 次，未触发。FP32 tile 容量不同，不能把相同 shape 的不同 dtype 合并判断。

未触发路径仍出现 0.3–2.6 μs 级回退，新增驻留逻辑/编译布局是待隔离验证的原因；现有 profiling 不能精确归因到单条分支。小输入 BF16 [3,5,1] 从 J015 3.195 到 J018 3.687 μs。600k 普通路径算法和源码未改，J018 对 J013 仅有约 0.02–0.10 μs 平均差值，不计为优化收益。

因此 J013 保持综合基线，J015 保留对齐 S=1 专项，J018 保留整核驻留专项；未生成新全量合并候选。下一项最直接的工作是对驻留路径做独立编译分派，未触发时使用原 J015/S=1 或 J013 普通路径，再以同一套输入回归；本轮没有实施这项新改动。

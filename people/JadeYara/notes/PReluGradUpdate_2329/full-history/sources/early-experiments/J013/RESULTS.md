# J013：J011 分核、J004 S=1、J008 UB 复用整合

## 结论

保留 J013 为新的整合候选，J003/J004/J008/J011 原版均保留。本轮 910C 原生编译通过，273/273 个精度输入通过；五版本两轮 540 组及定点四轮 160 组性能测试的最终输出也全部精确通过。未发现可持续复现的路径回退，暂不回退任何整合路径。

这次主要完成已有收益的合并。相对各专项版本的零点几微秒差值受到运行顺序/上下文影响，不能据此宣称额外加速。部分本地输入达到 4–5 us 以内；S=1 大通道、600k 和跨 tile 通道输入仍超过目标。榜单输入未知，不能推断平台得分或已超过 TBest。

## 实现与来源

- 普通路径使用 J008 kernel 原文件，SHA-256 `0b3155a845c434c585484f315a941e1beef945190efcf254f03b5ef1cab466a5`。Compare 完成后复用 featuresFloat 保存负分支结果，UB 系数 FP32=21、FP16/BF16=29。
- 通道权重且 S=1 使用 J004 kernel，仅改独立命名空间和头保护；权重队列、计算和同步序列不变，UB 系数 FP32=29、低精度=35。单权重 C=1 不误入此路径。
- tiling key 0/1/2 与 4/5/6 分派两套 kernel，普通路径没有运行时 S=1 判断。复用 J006 已编译过的 key 声明；并非恢复 J006 的 bool 模板改写或其未采用结论。
- wlen=1 使用 J011 `min(hardwareCoreNum,max(4,ceil(totalNum/1024)))` 目标核数，实际核数仍受 32B 对齐和有效块数量限制；wlen>1 使用硬件核数。未硬编码具体 shape。
- 没有引入 J007 双缓冲或 J009 权重缓存；没有改变 compare/select 语义、添加归约或调整浮点精度。

输入为固定 seed 的有限随机数、零值及既有全正/全负/边界组。golden 独立按 float32 中间运算后转目标 dtype，dx/update 数值完全一致，最大绝对误差为零。此处 273 是输入记录数，并非 273 个不同 shape；没有新增 NaN/Inf 专项或证明平台隐藏测试全覆盖，零的符号位不作为 np.array_equal 的差异。

性能：同一 batch runner 和独立 OPP 路径，54 输入 × 5 版本 × 2 轮；每输入 25 次调用、前 5 次丢弃、后 20 次 Task Duration 中位数。第二轮反转版本及输入顺序。CSV 按时间排序后逐组核实 shape、dtype、记录数，并对最终输出复核。随后针对异常及三条路径固定输入顺序、仅反转版本先后，做四轮交替：S=1 五输入、普通路径九输入、分核六输入，共 160 组。总计 700 组/17500 个 profiler kernel 记录。batch 绝对值不能与历史单独进程的计时混为同一口径。

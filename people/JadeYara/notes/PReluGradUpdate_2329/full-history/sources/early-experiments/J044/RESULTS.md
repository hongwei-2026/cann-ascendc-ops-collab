# J044：计时偏差复盘（910C / CANN 9）

结论：短算子计时仍有约 0.4–0.5 μs 的跨进程/窗口偏移，不能凭四轮均值中的小差异升级版本。已定位 graph profiling 的 Block Num 元数据/归一化异常，不能使用其 AIV、Vector、MTE 活跃时间评价硬件瓶颈。普通逐调用 profiling 的该项元数据正常，不能一并否定。

算子源码没有修改。运行器在 J035/J038/J043 上构建；本轮五个计时阶段实际测量的是 J038。五阶段全部退出 0，870 个输入窗口、20,016 个 event 样本；每窗口开始/结束检查两个输出，不是对每个内层 kernel 单独检查。另有 12,312 条 profiler kernel 记录。硬件 Ascend910_9362，编译 ascend910_93，CANN 9.0.0。

## 已完成的控制实验

1. pilot：同步逐调用、连续 enqueue、graph 三模式，32/128 次一批。目标 FP32 `[127,8192,1]`：同步 event 约 31 μs/次，enqueue/graph 约 10–11 μs/次。前者包括主机空隙，不能视作单 kernel 的执行时长。
2. calibrate：12 个输入，四轮，批长 128/512，同进程相同 J038 的 A/B/B/A 标签对照；每窗口预热 10,240 次、记录 24 次批执行，统计后 20 次中位数。24 个输入×批长组合均满足 A/A 偏差不超过 max(0.1 μs, 2%)，但跨轮范围仍可达 0.6481 μs。A/A 通过不等于跨进程稳定。
3. profile：相同输入和批长下 N-P-P-N（关闭/开启 profiler），6 个输入，两种模式。profiler 能改变运行条件，不能将 event 差额全部解释成 kernel 工具开销。
4. persistent：每个进程内保留输入地址并运行四轮，重复两个进程。目标 FP32/FP16/BF16 的两个进程均值分别相差 +0.4087/+0.4396/+0.0573 μs。同进程大输入较稳，但部分其他输入仍有约 0.5 μs 变化；固定地址不是充分解法。
5. frequency：FP32 目标输入两个进程，各 24 窗口。第一个窗口中位数范围 0.5000 μs，第二个 0.0260 μs；两个进程中位数 10.8593/10.3750 μs。低负载 1 Hz npu-smi 观察到活动芯片负载中均为 1650 MHz，不能据此排除瞬态、内存/uncore 或缓存影响，也没有证据将该偏差归因于观察到的整核频率变化。

## graph PMU 异常的原始证据

同一 FP32 大输入，普通调用 Block Num=40，graph 记录 Block Num=1；Host/内核未改，输出一致。graph Vector 88.475 μs 约等于普通调用 2.212 μs 的 40 倍；graph AIV 约 317–342 μs，而 Task Duration 仍约 10 μs。原始 cycle 与频率、Block Num 的算术关系符合归一化缺失现象，但本轮未证明工具内部根因。

因此不使用 graph 的 AIV/Vector/MTE 时间作占比，也不自行除以 40 后宣称可信。Task 时间戳与 event 批间隔分列；不同口径不混成单一性能排名。证据见 local-control/J044-graph-pmu.log/json 和 archive 内原始 profiler CSV。

普通调用 profiler 目标输入 J038：FP32 Task 10.610 / AIV 8.598 μs；FP16 11.380 / 9.335 μs；BF16 11.660 / 9.429 μs。这不是官方五点，不可与 1148578 逐点映射。

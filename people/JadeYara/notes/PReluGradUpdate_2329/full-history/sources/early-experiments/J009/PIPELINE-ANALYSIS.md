# 哪个环节占比最大：本轮实测解释

按msprof报告的流水线活跃比例，小BF16和通道FP16输入以Scalar最高；大FP32以MTE2最高；大FP16/BF16的Scalar与MTE2接近。当前证据不能把这些活跃比例等同于独立、可相加的端到端耗时，也不能据此认定唯一的关键路径。

下面统一使用本轮J009对照实验中的J008版本，避免混合旧轮次。每项为25次调用丢弃前5次后，20条记录的中位数；“a / b”为正向/反向两轮。Task Duration和aiv_time单位μs，其他列为msprof原始ratio×100%。这些比例不是Task Duration的独占百分比；不同流水线可以同时活跃。

Scalar包含标量控制/地址与索引处理等流水线活动；MTE2对应搬入方向，MTE3对应搬出方向，Vector对应向量指令活动。活跃高不自动证明该单元吞吐饱和，也不能把活动时间全部归因于某一源代码行。当前PipeUtilization数据没有提供逐行独占延时、HBM带宽饱和证明或完整关键路径分解。

例如小BF16第二轮Task Duration=4.930μs，而aiv_time=2.987μs；两者差额不能直接命名为CPU调用或固定launch耗时。当前也没有足够证据把同步等待单独量化为多少μs。

本次J009缓存移除了重复索引命中时的读取/解码/同步，但没有让多tile大输入获得明确净收益，且小FP32重复回退。因此不能依据Scalar比例高，就断言“权重读取是最大延时”。下一项优化应以受控改动后的总Task Duration是否稳定下降作验收，而不只看某个ratio下降。

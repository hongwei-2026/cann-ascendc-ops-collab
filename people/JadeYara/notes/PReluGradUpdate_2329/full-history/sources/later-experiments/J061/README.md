# J061：短S跨通道合批有效，但不直接晋升整包

2026-11-07 CST。仅完成用户同意的第一步短S验证；FP16计算精度优化未做。未官方提交、commit或push。J035/J056/J059/J060保持原样。

## 结论

[8,64,3]完整Task：FP32 10.80→6.64μs（38.52%）、FP16 11.47→6.47（43.59%）、BF16 11.36→5.88（48.24%），三者六轮均胜。36个实际启用输入中35个六轮改善；唯一启用退化是FP32[4,6,8]4.37→4.50μs（约2.97%）。它每核8元素恰好=S，实际上没有合并机会。

255/270控制组通过，15组未过原≤0.1μs且≤2%门槛。其中12组来自未修改算法的FP16 S=1：[127,64,1]6.47→7.74μs、[127,8192,1]11.78→12.30μs；其他3组来自两个FP32短S输入的A/C漂移。A/A最大0.12μs。因此短S假设得到明显支持，但此别名工程不能直接替代当前包，也不把未改路径回退当作噪声忽略。

下一最小修正是结构性的：仅blockFactor>S才启用合批，并让新分支只实例化匹配dtype的有效schMode。当前schMode<4条件把原来128B的无效key也展开成4–5KB，这是真实编译膨胀；是否解释S=1性能回退仍需对照，不能先下因果结论。本轮不扫描tile/核数，不重复刷控制门槛。

## 实现与同伴经验

A/C冻结J035，B只变短S=2..32、distinct-channel weights。保持核数/blockFactor，取消S边界处整套CopyIn/Compute/CopyOut截断，Host额外预算每元素4B的FP32权重缓冲。FP32总25B/element，FP16/BF16 33B/element，仍按既有80%可用UB预算。数学仍FP32 Mul、GT Compare+Select与CAST_RINT，不做掩码乘法、不改NaN分支。

从每核实际globalStart+progress取w[((index)/S)%C]。周期L=lcm(C*S,8)，不足tile时用32B对齐UB DataCopy倍增，V屏障分隔；tileLen不是C*S倍数则每tile按新相位重建，不能错误驻留。Duplicate用uint64_t mask[2]按位重载，基址floor(offset/8)*8始终32B对齐，S≤32使最高有效位≤38。不是把位图传给表示count的标量mask重载。

同伴P031/EXP018实证：直接从未对齐localOffset Duplicate曾导致官方case4 ACL507035；yuhongming新源码用SetValue前缀+对齐Duplicate修复，台账记载1–5 Pass。这里借鉴跨通道处理/合法对齐原则，没有复制旧错误实现。J043实际是S=1 split-C轮转，不是短S广播失败。

对[8,64,3]，真实分核下FP32原538个微tile→39个连续tile，FP16/BF16原512→32。538包括核边界额外切断，不能笼统都写512。几何计数是源码推导，不是硬件DMA计数。

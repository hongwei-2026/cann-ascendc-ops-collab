# J054：FP32 紧凑缓冲与两行合批

2026-11-05，已完成，不采纳。用户授权工程和必要设备对照，官方提交由用户执行。

唯一目标：在保持 J035 分核、语义和低精度路径的情况下，验证 FP32 split-C 紧凑布局，以及其上两行合批的完整 Task 收益。A=冻结 J035 机械改名；B=紧凑 mask + 生命周期复用单行；C=B 的两行版本。改动只在个人实验目录，不覆盖 workdir/code。

已核对公开 main a68973e，朋友 EXP005 Select 别名失败、P102/P104 平台退化、自己的 J029/J032/J034/J035/J039/J042 记录。这里不重做队列配对、提前释放或盲删屏障；四个长数组的实际复用需要输入完成、Vector 完成、输出完成三段同步。

计算顺序：零填 dx；product=f*g；Compare(f,0)；Select(f,0,product) 生成 update；此后 product 复用于 g*w；Select(dx,g,product)。两个 Select 的目标均与两个源不同。g/f、g/w、f/zero、g/product、zero/product 的源相位相差 256B modulo512。

两行 4096 通道 UB：4×32768 + 16384 + 1024 bit-mask + 768 padding = 149248B；软件预算 (196608−8192)×4/5 向下取整 = 150732B。已读取当前 Ascend910_9362.ini，ub_size=196608。Select 暂存仍由 Host ReserveLocalMemory(8K) 预留。实际 CANN9.3 dav_c220 CompareCompute 以元素数/8 推进输出，Select 使用 TMP_UB_OFFSET；不将紧凑 mask 当成新的数值表达。

范围：仅 FP32 split-C、tileLen≤4096、C%64=0，尾行由 rows=min(2,remaining) 处理；通道尾块宽度为 min(tileLen,C−offset)。其他路径保持 J035。C=64 广播在这轮结果后再决定。

验证计划：复用既有精度数据和同进程 A/A/B/C runner，覆盖目标、奇偶批次、较窄通道块、合法通道尾块及未改 dtype/路径控制；每窗口350次丢弃200，采用既有六种顺序。先正确性，再性能；失败原文与结果留存。

## 构建、正确性和失败

环境：同一 910C / Ascend910_9362，CANN9.3.0，compiler/OPP9.3.0-beta.1，driver25.5.5；私有包，无系统安装。

首次构建 exit2：AllocEventID 返回 TEventID，赋给 event_t 需显式转换。修复后 all/binary/package 和 runner 全部通过，exit0。首次测试 exit2：新增输入写在根目录，而既有 runner 读取 input/；此前 27 个窗口、432 次正确性调用已通过。修正数据路径后按完整计划重跑，最终 23 个输入、69 个窗口、744 次调用全部通过，每次比对两个输出，允许正负零等价。新输入包括两行 mask 符号差异、交替 lane、全负、零及 [81,8128,1] 通道/批次尾块。未修改比较标准。

A 的45个函数体与 J053 中的冻结 J035 完全相同。三别名合计135个函数体中125个一致；B/C 各5个 FP32 函数体不同，其中4个回退函数长度相同但字节不同，不能声称所有未改路径二进制相同。低精度函数体一致；实测控制均稳定。

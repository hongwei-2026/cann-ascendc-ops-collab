## 已定位的两个不同问题

### 目标包回退：J077 已定位

设备实际报告 Ascend910_9362。默认 ascend910b 包缺少对应 910_93 注册，运行日志显示自定义 Host 与 SDK built-in TBE Kernel 混用，报 507035。相同程序/输入，只改目标元数据的诊断副本可通过；9 个 .o 与原生 910_93 构建逐字节相同。这支持包查找/回退解释，不支持“9 个内核机器码本身不兼容”的解释。元数据改名只是诊断，不能作为通用跨型号部署方法。

J077 build.sh 增加显式 `--soc ascend910_93`，把目标纳入构建指纹；保留官方默认 ascend910b。设备与模拟器结果分开记录。

### 多别名计时偏差：J079 尚未解决底层原因

BF16 A/B/C 的完整 .text 与 .data 相同，实际 target/key/blocks 等已核对。慢速跟首次加载位置及进程状态有关；不是每个进程第二位置都慢，关闭流水线计数器也不能持续消除。不能凭这个现象断言温度、降频、I-cache、地址布局或某个硬件单元是原因。不能给 J078 减去固定偏移“修正”成绩。

## 必须保留的数值合同

neg=select(x>0,0,1)，pos=select(x>0,1,0)。dx=(pos+neg*w)*g，先量化到输出 dtype；update=(neg*x)*g+float32(quantized_dx)*0，再量化。各 dtype 的中间计算链按真实 TBE 证据保留。异常值、有限溢出、量化回读不允许凭代数直觉删掉；update 逐元素，不归约。

输出 shape=broadcast(grads,features)，weights 只能广播至输出。支持边界按 ND/NCHW/物理 NC1HWC0、实际 TBE 接受描述分别验证。被 TBE 拒绝的两个描述不能计 PASS；CPU 模型对历史 NPU oracle 通过不能写成又做了一轮设备测试。详见 [J077 合同](experiments/J077/TBE-CONTRACT.md)。

```bash
source /path/to/cann/set_env.sh
export GTEST_SOURCE_DIR=/path/to/googletest
export NLOHMANN_JSON_INCLUDE_DIR=/path/to/json/include
bash build.sh --soc ascend910_93 -j4 -u
```

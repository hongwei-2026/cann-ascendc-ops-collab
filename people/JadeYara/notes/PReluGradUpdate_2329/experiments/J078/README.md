# J078：FP16 未使用临时缓冲初始化 — 不采纳

日期：2026-11-08。结论：正确性通过，但未形成可采纳的性能收益。保留官方 1221802 性能基线，采用 J077 的复现/UT 修复。本轮未进行官方提交。

## 单变量边界

从官方 1221802 原始源码独立出发，仅修改 scalar、S1、merged、resident 四个 Init 中的一处条件：不再给 native half 路径初始化未使用的 gradsFloat/featuresFloat/dxFloat/updateFloat 四个临时缓冲。

这四个缓冲仅由非 half 计算分支读取。运算链、异常传播、dx 量化回读、Host、tiling key、分核、tile、队列、同步及既有数据缓冲位置不变。未叠加 J073 或 J076 优化。构建与 UT 使用 J077 的修复工具。

对照包 A/C 均为官方基线，B 为候选，标准候选另行构建。实际 CANN 9.3.0-beta.1、Ascend910_9362、目标 ascend910_93：

- A 与官方基线：189/189 函数体一致。
- A/C：189/189 一致。
- 标准候选/B：189/189 一致。
- A/B：174/189 一致。差异为三种格式下 FP16 key 1/4/7/10/13；key13 长度不变但字节不同，未擅自忽略。
- 四条目标 FP16 路径函数长度分别从 4292/4856/5272/6792 B 降至 4016/4664/5080/6620 B。代码体积减少不等于性能收益。

## 完整性能观察

沿用原有全部 127 个输入，没有增加或挑选有利 shape。六种 A/A/B/C 顺序，每窗 350 次、丢弃前 200 次、保留 150 次；共 3048 窗口、1,066,800 条 kernel 记录。原始 CSV 的数量、别名、顺序、shape、dtype、地址与窗口对应检查通过。

全部输入中 35 个观察到更快、30 个持平、62 个更慢。原始全体几何平均加速比为 0.9945，不能据此宣称收益。

控制门槛为绝对差不超过 0.1 μs 且相对差不超过 2%。762 组中 682 组通过、80 组失败：79 组 BF16，1 组 FP32。单看 A/A 则为 761/762 稳定。因此异常不能笼统归为随机 A/A 波动。

13 个 BF16 输入在六轮都出现 B 回退。例如 [127,64,1]：A1/A2/C 均约 7.20 μs，B 约 8.16 μs。相应 BF16 核函数体未改，整体包、装载或运行时因素尚未隔离；本轮不把回退归因于某个未经验证的机制。

## 决定与证据

J078 不采纳，不替换官方基线。FP16 中位节省太小，整体中位收益为零，且未改路径控制异常明显。保留原始六轮结果，未重跑失败控制，也未过滤异常后重新宣称通过。

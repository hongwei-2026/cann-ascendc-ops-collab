# DEC001 — 采纳 P004 有限收益，冻结 Kernel，先平台复测

2026-11-10；hongwei-2026；ConfusionTransposeD_2323。

## 证据

P004/EXP_C004 在 910B3、CANN 9.1.0 对比 545f8d2 与 4761239；原版和候选样例均通过，22/22 逐字节回归一致。连续行的三个 case 加速 2.09×、2.25×、6.07×；rank2 回退 0.993×。未达到立项 ≥10×，未取得平台复测或同机 TBE。

原始包、全文日志、CSV、源码及来源校验已归档到 EXP_C004。每组 25 次调用，按预定规则排除前 5 次；样例候选后 20 次范围 3.90～7.26us，中位数 4.06us；不能隐藏波动或另选 warmup 以扩大收益。

## 瓶颈/测量结论

- 连续行 DMA 确实减少标量负担并加速；half case 的 scalar 比率仍约 0.504，行级映射/DMA 发射可能继续占用时间，尚无新路线的直接证据。
- span=1 的 rank2 完全没有消除逐元素标量瓶颈；不以微调原标量循环重开。
- 平台报告 1.70～1.82ms，而相同原版在本轮四个已知 case 仅 8～41us；未知 case、版本、计时范围、运行方式均待核定。仅凭平台表无法将全部约 500× 差距定性为 Kernel 性能。
- 平台最优 3.43～3.66us 不是同机同 shape TBE，不能套用其他题 95% 或 3us 条款。

## 决策

1. **采纳 P004 的已验证代码作为下一次平台候选**，保留原功能精度及边界；不是宣称性能目标已全部完成。
2. **结束本轮 P004 调优并冻结 Kernel**。本轮没有耗尽 2 小时小 shape 上限，也没有两条互斥失败路；这是有界路线的主动结案，避免在缺平台证据时扩大调优。
3. 下一闸是平台重提 4761239 的精确代码并回收点 1～5 用时、可得的 case 信息与打分；本地准备对应代码包。
4. 若仍为 ms 量级，优先查平台计时/提交版本/case 对应关系；若确认 span=1 或特定主路径不足，再登记 P005，验证 910B Gather/Transpose 等新假设。当前不开 P005、不改超 UB 分块。
5. 不申请或宣称豁免；只有本题任务书条款及同机对照齐全后才考虑。

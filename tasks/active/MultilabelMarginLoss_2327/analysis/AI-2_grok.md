## 1. 一句话路线

按行切核，一行只归一个核：用 target 前缀（遇第一个 `<0` 即停）把 `is_target` 写成 **int32 出现次数**；在 float32 里对「`cnt[j]==0` 的类 × `cnt[l]>0` 的类」计算 `cnt[l] * relu(1 + x[j] - x[l])`，再除以 `C`；`none` 各核写自己的 `y[n]`，`mean`/`sum` 用 fp32 workspace **按核序**收成 shape `[1]`；fp16/bf16 只在最后写 `y` 时舍入。类轴按 UB 分块，整行放得下时块长就是 `C`。

## 2. 语义与验收门禁理解

### 2.1 金标准（`reference.py`）

输入：

| 张量 | 形状 | dtype |
|------|------|--------|
| `x` | `[N, C]`，reference 按二维解包 | fp32 / fp16 / bf16（OpDef 三档，且三档的 target 都是 int32） |
| `target` | `[N, K]`，`K` 可以不等于 `C` | int32 |
| `reduction` | 字符串属性，默认 `"mean"` | `"none"` / `"mean"` / `"sum"`（reference 也接受 0/1/2） |

输出：

| 张量 | 形状 | dtype | 容差（样例 case） |
|------|------|--------|-------------------|
| `y` | `none` → `[N]`；`mean`/`sum` → **rank-1 的 `[1]`** | 与 `x` 相同 | rtol = atol = `1e-4` |
| `is_target` | **`[N, C]`**（跟 `x` 的类轴，不跟 `K`） | **恒为 int32** | rtol = atol = tol = **0** |

每行 `i`：

1. 从左扫 `target[i, 0:K]`，遇到第一个 `<0` 就停。停点之前、且落在 `[0, C)` 的下标 `t` 使 `cnt[i, t] += 1`。`>= C` 的值跳过，不截断。`-1` 只是「任何负数」的常见写法，截断条件是 `<0`，不是「等于 -1」也不是「`>0` 才算标签」（**0 是合法类**）。
2. `is_target` 就是这个 `cnt`，原样以 int32 写出。重复标签累加。没出现的类必须是 0。
3. 损失（无正计数则该行为 0）：

```text
losses[i] = (1/C) * Σ_{j : cnt[j]==0} Σ_{l : cnt[l]>0}  cnt[l] * max(0, 1 + x[j] - x[l])
```

4. `none` 输出 `losses`；`sum` 输出 `Σ losses`；`mean` 输出 `Σ losses / N`。`/C` 已经在行损失里，`mean` 只再除一次 `N`。
5. 累加中间量按 reference 的说明用 float32，**最后一次**再落到 `y` 的 dtype。reference 的 CPU 侧用 float64 做配对求和再 cast；设备侧没有 float64 向量，P0 用 fp32 顺序归约，大 `C` 的舍入差单独作为精度风险（§6），不在 P0 上模拟 float64。

`j` 的集合是「整行从未出现的类」，不是「当前这个 `l` 以外的类」。类只要出现一次，就永远不进 `j`。因此 `j == l` 的自配对（hinge 恒为 1）不会混进来。`cnt[l]` 必须乘进去：同一类出现 4 次，就等价于前缀里 4 个位置各加一遍。只对 unique 类加一遍，`y` 会错；只把 `is_target` 收成 0/1、损失仍按位置展开，则 `y` 可能对、`is_target` 仍会错。两处都要按 reference 做。

`mean`/`sum` 必须是 **1 元素的一维数组**。reference 写明：0 维标量过不了判题机的 `Expect np.ndarray of dtype[shape]`。

### 2.2 首个样例已经覆盖「计数 + 截断」

`sample.py` / `case.json`：`x`、`target` 都是 `[4, 6]`，`reduction="mean"`，`y` 为 fp32 `[1]`（4 字节），`is_target` 为 int32 `[4, 6]`（96 字节，逐元素相等）。`rng.integers(-1, 5)` 的上界是开区间，实际取值 `-1..4`，在 `C=6` 下都是合法类或截断符，**样例本身不会出现 `t>=C`**。

同一 seed 复算的 target 与 `is_target`：

```text
target
[[ 3,  3,  3,  0,  1,  1],
 [ 1, -1,  2, -1,  3,  3],
 [ 4,  3,  1,  4,  1,  0],
 [ 4,  1, -1,  1,  3,  0]]

前缀长度 end = [6, 1, 6, 2]

is_target
[[1, 2, 0, 3, 0, 0],
 [0, 1, 0, 0, 0, 0],
 [1, 2, 0, 1, 2, 0],
 [0, 1, 0, 0, 1, 0]]
```

- 第 0 行没有负数，类 3 计 3、类 1 计 2。写成 0/1 会得到 `[1,1,0,1,0,0]`，整数容差 0，直接 WA。
- 第 1 行在第二个位置截断。后面的 `2,3,3` 全部忽略，`is_target` 只有类 1 为 1。扫完整行会把类 2、类 3 算进去。
- 第 3 行只保留 `[4, 1]`，后面的 `1,3,0` 忽略。
- 复算行损失约为 `[7.863, 0.526, 0.527, 1.510]`，`mean ≈ 2.607`。量级是 O(1)，这个小 shape 用 fp32 对 `1e-4` 很宽裕；它不能代表大 `C`。

`K=C=6` 时，`is_target` 的形状碰巧等于 target。**这个样例发现不了 `K≠C`。** 例程 `test_aclnn_multilabel_margin_loss.cpp` 也把形状写死成 `y{1}`、`is_target{4,6}`、属性 `"mean"`，同样发现不了 `none` / `sum` / `K≠C` / fp16 / bf16。

`sample.py` 的比较还有一条：`bad <= tol * numel`。`y` 只有 1 个元素且 `tol=1e-4`，只要有一个点超出 rtol/atol 就是 WA。`is_target` 的 `tol=0`，一个整数不同即失败。

### 2.3 模板现在实际在做什么

这些是空实现的行为，**不是**可以保留的合同。`tests/ut` 里 `expectTilingKey=1`、`expectTilingData="0 1 0 "`、`expectWorkspaces={0}` 的注释写明：期望值跟着初始模板走，改 tiling 后要改 UT。

| 位置 | 现状 | 和语义的差距 |
|------|------|----------------|
| `InferShape` | `y ← x` 的形状，`is_target ← target` 的形状 | `mean` 的 `y` 应是 `[1]`，现在会变成 `[N,C]`。`K≠C` 时 `is_target` 会变成 `[N,K]` |
| `Tiling` | `totalNum=0`，`blockFactor=1`，`ubFactor=0`，`SetBlockDim(1)`，workspace `0` | 单核占位；三个字段是逐元素模板，没有 `N/C/K/reduction` |
| TilingKey | fp16 **或 bf16** → key 0；否则 key 1 | key 0 的内核写死 `half`。bf16 会按 fp16 比特解释 |
| `tiling_key.h` | `schMode` 只有 1 bit，取值 0 和 1 | 放不下第三种 dtype，除非另加 TilingData 字段并在内核里再分支 |
| Kernel | `Init/Process` 为空；队列只有 `x` 和 `y` | target / `is_target` 的 GM 指针没接上。空内核按 README 会校验失败，这是预期现象 |
| OpDef | 只注册 `ascend910b`，ND，`reduction` 默认 `"mean"` | 与「只做 910B、ND、字符串归约」一致，P0 不要扩 SoC / 格式 |

Host UT **没有** InferShape 用例锁住错误形状，所以 InferShape 可以按语义改，不会被现有 UT 的「拷贝输入形状」绑死。Tiling UT **会**被新的 TilingData / workspace 打红，改字段时同步改期望，不要为了维持 `"0 1 0 "` 留着空 tiling。

### 2.4 性能门禁与小 shape 豁免

`TASK.md` 把性能写成**待核对**：同系列惯例是全核场景不低于原 TBE 的 95%，小 shape / 10µs 级有豁免叙事；正式句子以平台/赛题 PDF 为准。本仓 `02-perf-gate.md` 的默认分流可以先用来止损，其中「10µs 以下相差 3µs」的原文是 PRelu 任务书示例，**不能直接写成 2327 已经生效的条款**。

| 类 | 本题怎么归 | P0 阶段的态度 |
|----|------------|----------------|
| A 全核主路径 | 多行、大 `C`，reference 提到过 `[512, 4096]` 这种量级。核数以 `GetCoreNumAiv()` 为准，不写死 | 先做正确、可多核的行并行。没拿到同机 TBE 对照表之前，不做性能专题 |
| B 小 shape | 首样例 `[4,6]`，计算量是每行几十次 hinge，耗时几乎全是启动和搬运。若平台确认有 10µs/3µs 条款，它落在 B 类 | **优先**仿真图 + 分析。未核对前也不对它做微秒级死磕（仓内上限 2 小时，然后停） |
| C 非门禁 | 平台没列进性能表的极端形状 | 正确性要过（泛化），性能只记录 |

小 shape 豁免**有可能适用，现在还不能当已确认条款使用**。豁免只免除「抠到 95%」，不免除功能、精度和 `is_target` 的 0 容差。

功能侧已经写明的要求：对齐 TBE 核心语义、支持 OpDef 的 dtype 与 ND、**必须泛化**（验收数据不是这一个样例）。精度先按样例 `1e-4` / 整数全等；fp16、bf16、大 `C` 的平台阈值都还没出现在材料里，见待核对。

### 2.5 待核对（不猜完就写进实现）

1. 正式性能条文是否就是「全核 ≥ TBE 95%」以及「<10µs 且差 ≤3µs 可交仿真」。
2. 平台是否只发二维 `[N,C]` / `[N,K]`。reference 对一维会在解包时失败。建议 P0 **只接受两维且两输入的 N 相同**，其它 rank 在 Host 返回失败。若后来出现一维用例，再单独立项。
3. fp16/bf16 的 rtol/atol，以及大 `C` 时 fp32 归约相对 reference float64 的允许误差。
4. `N=0` 或 `C=0`（`/C`、`mean` 除零）会不会出现。
5. `reduction` 是否只会出现小写三值。OpDef 是字符串；非法值按 reference 的态度在 Host 失败。
6. CANN 9.0/9.1 里 bf16 的类型名、`Cast` 的舍入模式，以及 AIV 上 `SyncAll` 的可用名字。下文按「fp32 部分和 + 核间同步 + 0 核收尾」描述行为，API 以当前工具链头文件为准。
7. 系统 workspace 是否必须非 0。模板现在写 0，UT 也期望 `{0}`。用户区按部分和实算；若运行时另有系统段要求，按报错再加，不先写死 16MB。

## 3. 最简正确实现路径

「最简」指一条按行处理的向量内核，而不是逐元素骨架，也不是先写标量 `C×C` 再改向量。内层对 `j` 做 relu，是这个公式在 Ascend C 上的直接写法：每对 `(l, j)` 都要看，算术量本来就是 `O(T·C)`。标量双循环在 `[512, 4096]` 上会把功能用例拖超时，不把它当基线。

### 3.1 InferShape

读取 `x`、`target` 与 `reduction`（缺省当 `mean`）。

- 要求二者均为 2 维，且 `target.dim[0] == x.dim[0]`。记 `N = x.dim[0]`，`C = x.dim[1]`，`K = target.dim[1]`。`K` 只参与扫描，不参与输出形状。
- `y`：`none` → `[N]`；`mean` 或 `sum` → `[1]`（`DimNum=1`，不要 0 维标量）。
- `is_target` → `[N, C]`。dtype 由表驱动保持 int32，不要跟着 target 的 `K` 走，也不要跟着 `x` 的浮点类型走。
- `y` 的 dtype 跟 `x` 的三档表走（fp32 / fp16 / bf16）。

### 3.2 Tiling 与 TilingData

丢掉「总元素 / 每核元素 / UB 元素」这三个逐元素字段，改成行语义（名字可调整，字段必须能表达下面的量）：

| 字段 | 含义 |
|------|------|
| `N, C, K` | 行数、类数、target 宽度 |
| `reduction` | 0 none / 1 mean / 2 sum |
| `usedCores` | `N>0` 时为 `min(N, aivNum)`，否则不要 `SetBlockDim(0)` |
| 行切分 | 前 `N % usedCores` 个核多 1 行，其余 `N / usedCores` 行。核 `b` 能算出自己的 `[rowBegin, rowEnd)` |
| `tileC` | 类轴分块。UB 放得下整行时 `tileC = C` |

`SetBlockDim(usedCores)`。没有行的核不要拉起来：空核若参加 `SyncAll`，归约个数会和 `usedCores` 不一致。

UB 估算用本核 `GetCoreMemSize` 的真实值。模板 UT 里的 `262144` 只是 faker，不要写进算子。一块里需要同时放下的大致是：`x` 的 fp32 块、`cnt` 的 int32 块、hinge/mask 临时块、一块 target。910B 上 `C=4096`、`K=4096` 时整行大约几十 KB，通常可以 `tileC=C`。`C` 再大到整行超过 UB 时，缩小 `tileC`，**同一套循环**多走几块，不另写一套算法。

Workspace：

- `none`：用户区可以是 0。各核写互不相交的 `y[row]`。
- `mean`/`sum`：`usedCores` 个 **fp32** 部分和（每个核把自己那些行的 `losses` 先加好）。不要为每个元素再开一块。

Tiling 里把 `reduction` 变成枚举写入 TilingData。内核侧按模板惯例读 tiling，不读属性字符串。

### 3.3 TilingKey

三档输入各一个编译期实例，计算过程都是 fp32，差别只在 `x` 的加载和 `y` 的回写：

| key | 实例 | 谁进来 |
|-----|------|--------|
| 0 | `half` | 仅 fp16 |
| 1 | `float` | fp32（与现有 UT 的 key `1` 对齐，少改一处） |
| 2 | bf16 类型（9.0/9.1 头文件里的 `bfloat16_t` 或同等名字） | 仅 bf16 |

现在的 key 0 把 bf16 和 fp16 绑在一起，并且 `UINT` 只有 1 bit。P0 要加宽 `schMode`（或增加一个编译期 dtype 分支），让 bf16 有自己的加载/存储。不要用 `half` 去解释 bf16 的比特。

### 3.4 Kernel（每个核处理自己的行）

对每一行：

1. **计数，并写出这一行 `is_target`。** 先把该行清零（只清自己的 `[row, 0:C)`，不要整表清零）。再按块读入 target，遇到第一个 `<0` 停止；`0<=t<C` 则 `cnt[t]++`。整行能留在 UB 时，在 UB 里计数，然后 `DataCopyPad` 写出 `C` 个 int32。整行放不下时，对 `is_target` 的对应块做加载—加一—存回；这一行仍然只有本核在写，不用原子加。
2. **行损失。** 若没有任何 `cnt>0`，或每个类计数都 `>0`（没有 `j`），损失为 0，但第 1 步的计数已经要写完。否则在 fp32 中：
   - 先收出紧凑的目标列表 `(l, cnt[l], x[l])`。列表放不下 UB 就按目标分块重复扫 `j`。
   - 对每个 `j` 块：读入 `x[j]`（半精度先 `Cast` 成 fp32），读入同块 `cnt`。对列表中每个 `l`：`hinge = max(0, 1 + x[j] - x[l])`，乘 `(cnt[j]==0)` 的 0/1 掩码，再乘 `cnt[l]`，归约进一个 fp32 标量。
   - `loss = acc / (float)C`。
3. **写 `y`。**
   - `none`：把该行 fp32 损失 `Cast` 成 `y` 的 dtype，写入 `y[row]`。
   - `mean`/`sum`：本核先把各行损失加完，写入 `workspace[blockIdx]`（fp32）。`SyncAll` 之后只由 0 核按 `0 .. usedCores-1` 的顺序相加。`sum` 直接存；`mean` 再除以 `N`（除的是总行数，不是核数，也不是本核行数）。最后一次才 `Cast` 到 `y[0]`。

搬运：`C=6` 时一行 fp32 是 24 字节，不是 32 字节对齐。读用 `DataCopyPad`，计算只使用有效的 `C` 或 `K` 个元素，写出的长度也是有效元素个数。对齐填充留在 UB 里，不能写进下一行。

0 核收尾的顺序固定，避免原子加的浮点顺序漂移。`none` 路径不要 `SyncAll`。

### 3.5 这条路径覆盖样例，也覆盖样例没覆盖的合同

首样例（fp32、`mean`、`K=C=6`、4 行）会走到：4 个核各 1 行、`tileC=6`、workspace 4 个 fp32、0 核求出 `[1]`。第 0 行的计数 `3` 和第 1 行的截断都会被 0 容差看住。

## 4. 性能候选路径（有序、有止损）

进入条件（四条同时满足，缺一条就退回）：功能泛化全绿、精度达到当时已核对的阈值、**同机 TBE 对照表**已经记在 `path-ledger`、基线行结案为「功能精度采纳」。在此之前下面的条目只是排队，不开工。

| 顺序 | 做什么 | 针对什么 | 止损 |
|------|--------|----------|------|
| 0 | 用 §3 的行并行 + `j` 向量块做基线，并打对照表。先分开记：`[4,6]`、`N` 不能整除核数、`K≠C`、`[512,4096]` 量级、三种 dtype、三种 reduction | 确认时间花在 hinge 上还是花在启动上 | 没有 profile 不加新路 |
| 1 | 若对照落在 B 类（约 10µs 且与 TBE 的差距在条款允许范围内；条款未核对则先看是否已 <10µs） | 小 shape 启动开销 | 仿真图 + 分析后停止。微秒级最多 2 小时 |
| 2 | A 类未到 95% 时，先看是不是核没铺满、`tileC` 太小导致 `x` 反复从 GM 读、或 `none` 误走了同步 | 大 `N`、大 `C`，计算量 `O(N·T·C)`，字节量只有 `O(N·(C+K))`，大 `C` 应以计算为主 | 标准项 0.5～1 人日；相对上一版增益 <2% 就停 |
| 3 | 仍差一截：下一行预取 / 双缓冲。只在 profile 看到搬运气泡时做。大 `C` 且整行已在 UB 时，收益可能很小 | 大 `N`、中小 `C` 的带宽 | 同上，<2% 停 |
| 4 | 结构改动（须事先 DEC，≤2 人日）：`N` 远小于核数但单行 `C` 很大时，把 **`j` 轴**拆到多核，每核一个 fp32 部分和，仍由 0 核按序相加。`is_target` 仍由该行的属主核单独写完，再允许别的核读 | 例如 `N=1`、`C=4096` 的单行 | 到期必须继续 / 回退 / 豁免三选一。连续两条互斥的路都没到 A 类门禁，停止并写 DEC |

不把 Cube / 外积矩阵当候选。`relu` 在配对之后，外积矩阵是 `T×C`，大 `C` 放不进 UB，也用不上 Cube 的线性乘加。

## 5. 不要先做

1. **沿用逐元素模板。** `totalNum = N*C`、按 `ubFactor` 切平铺元素、`CopyIn/Compute/CopyOut` 当逐点算子。这个损失不是逐点函数，也不是给 `x` 套一个 mask 就结束。
2. **把 `is_target` 写成 0/1**，或按 PyTorch / 部分 aclnn 文档的「标记位」当 golden。首样例第 0 行就会在整数全等上失败。损失侧若不去乘 `cnt[l]`，同一行的 `y` 也会偏。
3. **多核一起写 `y[0]`。** 包括对 fp16/bf16 做原子加，以及「每核先对自己的行取 mean，再对核取 mean」。`N` 不能整除核数时，后者不等于 `sum/N`。首样例 `N=4` 若刚好一核一行，这个错误测不出来。
4. **用 `half` 实例跑 bf16**，或在 fp16/bf16 里做 hinge 累加，只在最后才转到 fp32。中间量保持 fp32，半精度只出现在读 `x` 和写 `y`。
5. **按 `C` 把同一行拆给多核去 `cnt[t]++`。** 计数会丢、会重，整数容差是 0。跨核切 `j` 是 §4 的第 4 步，而且计数必须已经由属主核写完。
6. **为小 shape 上 Cube、抠指令，或为了 UT 仍打印 `"0 1 0 "` 而保留 `blockDim=1` 和错误的 InferShape。** 也禁止把曾经合入又回退的 ops-nn AscendC 整段搬来当已经验收的实现（`TASK.md` 的非目标）。
7. **用 `j != l` 代替 `cnt[j]==0`。** 多标签时，别的目标类会被当成非目标，hinge 多加一截。

## 6. 本题特有风险

| 风险 | 为什么本题容易中 | 基线里怎么接住 |
|------|------------------|----------------|
| 计数 vs 0/1 | 文档叙述和 reference 不一致；样例第 0 行是 `[1,2,0,3,0,0]` | 按出现次数写 int32；自测含重复标签 |
| 第一个 `<0` 截断 | 样例第 1、3 行的 `-1` 在行中间，后面还有合法下标 | 前缀之后全部忽略；0 仍是合法类 |
| `t>=C` 与 `K≠C` | 样例 `K=C` 且取值都在 `[0,C)`，InferShape 又把 `is_target` 设成 target 的形状 | 输出锁 `[N,C]`；`t>=C` 跳过；单测 `K<C` 与 `K>C` |
| reduction 形状 | 模板把 `y` 设成 `x` 的 `[N,C]`；例程只分配了 `[1]` | `none→[N]`，`mean/sum→[1]`；三种都测。0 维标量不合格 |
| 除数 | `/C` 在行内，`mean` 再 `/N`。用 `K`、用目标个数、或再除一次 `C` 都会偏 | 公式按 §2.1；`C` 用浮点除 |
| bf16 / half | key 0 用 `half` 同时承接两种输入 | 独立 key；计算用 fp32；只 Cast 最终 `y` |
| 跨核写 `y` | `mean`/`sum` 只有一个元素；空核或原子加会让结果非确定 | 一核一行属主；fp32 workspace；0 核按核序加；`mean` 除以 `N` |
| 大 `C` 的 UB | `C=4096` 通常放得下；再大则 `x` 与 `cnt` 不能整行常驻。写出时若把对齐尾部也拷出去，会冲掉下一行 | `tileC` 按真实 UB 缩小；GM 写出长度是 `C` 不是对齐长度 |
| 大 `C` 的 fp32 归约 | reference 用 float64 求和。`T` 和 `C` 都是几千时，fp32 顺序和可能碰到 `1e-4` | P0 不模拟 fp64。真出现 WA 再作为精度项改归约顺序，不把它伪装成性能优化 |
| 未清零的 `is_target` | 整数一个不对即失败；截断行的尾部类必须是 0 | 属主核先清自己的行，再加计数 |
| 不对齐 | 样例 `C=6`，24 字节 | `DataCopyPad`，有效长度 `C`/`K` |
| 空目标 / 满目标 | 损失为 0，计数仍要正确 | 显式写 0，不留下未初始化的 `y` |

## 7. 建议执行顺序

分析定稿并得到 `SUMMARY` 之前，不进入下面的编码。顺序本身是给定稿后的实现用的。

### P0 — 正确性（功能 + 精度，含泛化）

1. InferShape：`y` 的 `[N]`/`[1]`，`is_target` 的 `[N,C]`，非法 rank / 非法 reduction 失败。
2. 换掉逐元素 TilingData；写入 `N,C,K,reduction,usedCores,tileC`；`blockDim=min(N,aivNum)`；`mean`/`sum` 申请 fp32 部分和 workspace。同步改 host UT 与 kernel UT 的 fixture。
3. TilingKey 拆成 fp32 / fp16 / bf16。bf16 不再进入 `half`。
4. 内核按 §3.4：截断计数、`cnt[l]` 加权、`cnt[j]==0` 掩码、fp32 hinge、`DataCopyPad`、按 reduction 写 `y`。
5. 自测至少包括：seed 42 首样例；`none` 与 `sum`；fp16 与 bf16（中间 fp32，只比较最终 `y`）；行中 `-1`、重复标签、`t>=C`、全 `-1`、所有类都出现；`K<C` 与 `K>C`；`C=6` 不对齐；`N` 不能整除核数（专打「各核先 mean」）；一行放不进 UB 的大 `C`（若构造得出来）。`is_target` 必须字节级全等。

P0 不做双缓冲、不做 `j` 跨核、不对 `[4,6]` 计时。

### P1 — 全核标准优化（仅 A 类未达标，且已有 TBE 对照）

按 §4 的顺序 2→3：先确认计算/带宽瓶颈和核利用，再决定要不要预取。每条路写入 `path-ledger`，时限 0.5～1 人日，增益 <2% 结案。B 类直接转仿真材料，不进 P1。

### P2 — 只有 P1 仍不够门禁

单行大 `C` 的 `j` 轴分核 + DEC。时限 ≤2 人日。做不到就回退到 P0/P1 的最快正确版本，小 shape 走豁免材料，不再换算法。

## 本路结论（供汇总，不是 SUMMARY）

- 采纳：行属主 + 前缀计数 + fp32 向量 hinge + reduction 分形状 + 半精度末端 Cast。
- 废弃到有新证据之前：0/1 标记、逐元素切分、`half` 兼做 bf16、多核抢写 `y[0]`、各核先 mean、`j!=l` 当掩码、为小 shape 上 Cube。
- 争议留给汇总时核对，不在本路写死：正式 95% / 10µs 条文、大 `C` 的 fp32 对 float64 是否越界、rank≠2 是否存在。
